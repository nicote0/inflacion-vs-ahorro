# M1 Ingesta — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Script de Node.js que descarga las tres series (IPC del INDEC, dólar y tasa del BCRA), guarda una copia cruda con fecha y hash, y calcula la frescura de cada fuente.

**Architecture:** Un adaptador por tipo de API (`indec_series`, `bcra_monetarias`) con la misma interfaz: descargar, parsear y leer la fecha declarada. Un módulo de almacén guarda las copias crudas y un manifiesto. Un módulo de frescura evalúa cada fuente. Un orquestador recorre `fuentes.json`, aísla los errores por fuente y escribe `data/frescura.json`.

**Tech Stack:** Node.js 24 (ESM, `fetch` nativo, `node:crypto`, `node:fs/promises`), tests con `node:test` y `node:assert/strict`. Sin dependencias externas.

**Spec:** `docs/superpowers/specs/2026-11-25-inflacion-vs-ahorro-design.md`. Issues: #20, #44, #22 y #24.

## Datos verificados el 26/11/2026 (insumo del plan)

**INDEC, API de series** (`https://apis.datos.gob.ar/series/api/series/`):
- `?ids=148.3_INIVELNAL_DICI_M_26&format=csv&start_date=2016-12-01&limit=1000` devuelve `text/csv` con el encabezado `indice_tiempo,ipc_nivel_general_nacional` y filas del tipo `2016-12-01,100.0`. Usa punto decimal. Son 119 filas (2016-12 a 2026-10).
- `?ids=...&limit=1&metadata=full` (JSON) trae `meta[1].field.time_index_end` (`"2026-10-01"`) y `meta[1].field.is_updated` (`"True"`). Es la fecha declarada.
- El límite de 1000 filas por pedido sobra para esta serie.

**BCRA, API v4** (`https://api.bcra.gob.ar/estadisticas/v4.0/monetarias`):
- Datos: `/monetarias/{id}?desde=AAAA-MM-DD&hasta=AAAA-MM-DD&limit=N&offset=K` devuelve `{"status":200,"metadata":{"resultset":{"count":C,"offset":K,"limit":N}},"results":[{"idVariable":4,"detalle":[{"fecha":"2026-11-25","valor":1632.65}, ...]}]}`. Viene ordenado de la fecha más nueva a la más vieja.
- `limit` vale 1000 por defecto y 3000 como máximo. Con más de 3000 responde 400 y `errorMessages: ["El límite no puede superar los 3000 registros."]`. Una variable inexistente también devuelve 400.
- La variable 12 tiene 2422 filas desde 2016-12-01, cerca del límite: hay que paginar.
- Catálogo: `/monetarias?limit=3000&offset=K` (4037 variables, 2 páginas). Trae `idVariable`, `descripcion`, `periodicidad`, `unidadExpresion` y `ultFechaInformada`. Es la fecha declarada.
- Variable 4: "Tipo de cambio minorista (promedio vendedor)", pesos por dólar, diaria.
- Variable 12: "Tasa de interés de depósitos a 30 días de plazo en entidades financieras", porcentaje nominal anual, diaria. Es el promedio de todos los depositantes. Se eligió sobre la 1190 ("personas humanas", todos los plazos) porque coincide con la renovación cada 30 días. La variable se configura en `fuentes.json`.

## Global Constraints

- Node.js >= 20, ESM (`"type": "module"`), sin dependencias de runtime.
- Las copias crudas van a `data/raw/`, que está en `.gitignore`. No se suben al repo.
- Nunca subir credenciales ni `.env`. M1 no usa credenciales.
- No se inventan ni se rellenan datos. Un valor vacío o no numérico se descarta y se cuenta.
- Si una fuente falla, se sigue con las demás. El proceso termina con código 1 si falló alguna.
- Las fechas de "hoy" se calculan en hora de Argentina (`America/Argentina/Buenos_Aires`).
- Un commit por tarea. Cada push se confirma con Nico antes de hacerlo.
- Textos, nombres de archivos y mensajes en español.

## Review Focus

1. **La API responde 200 pero con contenido que no es el esperado** (HTML de error o cuerpo vacío): se trata como error de la fuente y no se guarda como copia cruda. Lo cubren las Tareas 2 y 3 (`parsear` lanza error) y la Tarea 5 (no se guarda).
2. **El BCRA supera 3000 filas en un pedido:** se pagina por `offset` hasta llegar a `count`. Test en la Tarea 3.
3. **Una fuente caída o con timeout:** las demás se procesan igual y el código de salida es 1. Test en la Tarea 5.
4. **Feriados y fines de semana en series diarias:** no deben marcar la fuente como desactualizada. La tolerancia es de 5 días. Test en la Tarea 4.
5. **Ejecución cerca de medianoche:** "hoy" en UTC puede ser un día más que en Argentina. Test de `fechaHoyArgentina` en la Tarea 4.

## Tipos compartidos

```js
// Observacion: { fecha: 'AAAA-MM-DD', valor: number }
// Fuente (fuentes.json): { id, nombre, tipo: 'indec_series'|'bcra_monetarias',

//   descargar(fuente, { fetch, hoy }) -> Promise<{ contenido: string, extension: 'csv'|'jsonl' }>

```

`fetch` se inyecta para poder testear sin red. En producción es `globalThis.fetch`. Cada pedido usa `AbortSignal.timeout(30000)`.

### Task 5: Orquestador y CLI (#22, #24)

**Files:**
- Create: `pipeline/src/ingesta.js`, `pipeline/src/cli.js`
- Test: `pipeline/test/ingesta.test.js`

**Interfaces:**
- Consumes: `guardarCrudo`, `leerUltimoCrudo` (Tarea 1), `adaptadorPara` (Tarea 3), `evaluarFrescura`, `fechaHoyArgentina` (Tarea 4).
- Produces: `ejecutarIngesta({ fuentes, dirBase, fetch, ahora }) -> Promise<{ ok: boolean, resultados: Resultado[] }>`, donde
  `Resultado = { fuenteId, ok, sinCambios, sha256, archivo, filas, descartadas, error: string|null, frescura: { ultimaObservacion, ultimaFechaDeclarada, ...evaluarFrescura(), fechaChequeo } }`

Flujo por fuente, dentro de un `try/catch` propio:
1. `descargar`.
2. `parsear`. Si falla, la fuente queda con error y **no** se guarda la copia.
3. `guardarCrudo`.
4. `declarado`. Si falla, `ultimaFechaDeclarada` queda en `null` y la fuente sigue `ok`, pero el error se anota.
5. `evaluarFrescura` con la última observación.

Si la descarga falla y existe una copia anterior (`leerUltimoCrudo`), la frescura se calcula con esa copia. La caída no oculta hasta cuándo había datos.

`cli.js` usa `dirBase = <raíz del repo>/data/raw`, `fetch = globalThis.fetch` y `ahora = new Date()`. Escribe `<raíz>/data/frescura.json` con `{ generado: ISO, resultados }` y muestra una línea por fuente: `ok  ipc_nacional  119 filas  sin cambios  vigente (26 días)`. Si algún resultado tiene `ok: false`, sale con `process.exitCode = 1`.

- [ ] **Step 1: Write the failing tests**, con adaptadores y `fetch` falsos:
  - `una fuente caída no frena a las demás`: si la segunda fuente lanza error en `descargar`, la primera y la tercera dan `ok: true` y el total da `ok: false`.
  - `contenido inválido no se guarda`: si `parsear` lanza error, el manifiesto no tiene entrada para esa fuente.
  - `fuente caída con copia previa calcula frescura con la copia`.
  - `segunda corrida sin cambios`: `sinCambios: true` y la frescura se calcula igual.
- [ ] **Step 2: Run** `npm test`. Expected: FAIL.
- [ ] **Step 3: Implement** `ingesta.js` y `cli.js`. Para que el orquestador se pueda testear con adaptadores falsos, `ejecutarIngesta` acepta un parámetro opcional `obtenerAdaptador` (por defecto `adaptadorPara`).
- [ ] **Step 4: Run** `npm test`. Expected: PASS con todos los tests.
- [ ] **Step 5: Verificación real** (verification-before-completion): `cd pipeline && npm run ingesta`. Expected: 3 líneas `ok`. `ipc_nacional` con 119 filas o más y último dato `2026-10-01` o posterior. Las dos series del BCRA con más de 2400 filas. Las tres `vigente`. Existe `data/frescura.json` y los archivos están en `data/raw/`.
- [ ] **Step 6: Verificación de no duplicar:** correr `npm run ingesta` otra vez. Expected: `ipc_nacional` dice "sin cambios" y el manifiesto no suma entrada para esa fuente. Las del BCRA pueden cambiar si se publicó un dato nuevo entre corridas.
